# WeTravel: System Architecture & Complete Backend Documentation

---

## 1. Project Overview & System Scope

**WeTravel** is a distributed, AI-assisted group travel planning, expense tracking, and coordination platform. It solves common group travel challenges—including divergent travel personas, mismatched budgets, manual receipt calculations, post-trip financial disputes, chat clutter, and dynamic travel disruptions.

```
                     ┌────────────────────────────────────────────────────────┐
                     │            Client (Web / React Native / Flutter)       │
                     └───────────────────────────┬────────────────────────────┘
                                                 │ HTTPS / WSS
                                                 ▼
                     ┌────────────────────────────────────────────────────────┐
                     │                  NGINX / API Gateway                   │
                     └─────────────┬────────────────────────────┬─────────────┘
                                   │                            │
                      /api/*, /ws  │                            │ /api/ai/stream/*
                                   ▼                            ▼
            ┌───────────────────────────────┐     ┌──────────────────────────────────┐
            │ Node.js Orchestrator          │     │ FastAPI AI Microservice          │
            │ - Port 3000 (Express)         │     │ - Port 8000 (Uvicorn)            │
            │ - Prisma ORM (Relational)     │     │ - SQLAlchemy + pgvector-python   │
            │ - Business Logic & WebSockets │     │ - In-Memory NLP / Vision / OCR   │
            └──────────────┬────────────────┘     └──────────────────┬───────────────┘
                           │ Internal HTTP (Fire-and-forget)         │
                           └─────────────────────┬───────────────────┘
                                                 │
                                                 ▼
            ┌────────────────────────────────────────────────────────────────┐
            │              PostgreSQL 16 + pgvector Database                 │
            │           (Unified Relational + 384-d Vector Store)            │
            └────────────────────────────────────────────────────────────────┘
```

The system separates high-concurrency relational input/output and user session lifecycle management from compute-heavy vector similarity operations, optical character recognition (OCR), and deterministic scheduling algorithms.

## 2. Layered Architecture Principles

Both microservices follow a strict separation of concerns:

```
[HTTP Request / WebSocket]
         │
         ▼
 ┌───────────────┐
 │    Routes     │  Validates endpoints, extracts path parameters, applies guards.
 └───────┬───────┘
         │
         ▼
 ┌───────────────┐
 │  Middleware   │  Validates JWT signatures, enforces RBAC (creator/admin/member).
 └───────┬───────┘
         │
         ▼
 ┌───────────────┐
 │  Controllers  │  Parses request bodies, normalizes HTTP response schemas.
 └───────┬───────┘
         │
         ▼
 ┌───────────────┐
 │   Services    │  Executes core business logic, algorithms, and WebSocket events.
 └───────┬───────┘
         │
         ▼
 ┌───────────────┐
 │ Repositories  │  Direct database queries via Prisma ORM / SQLAlchemy.
 └───────┬───────┘
         │
         ▼
 ┌───────────────┐
 │ PostgreSQL DB │  Stores relational records + 384-dimensional vector embeddings.
 └───────────────┘
```

## 3. Environment Setup & Getting Started

### 3.1 Prerequisites
- **Node.js**: v18.0.0 or higher (v20+ recommended)
- **Python**: v3.10 or higher
- **PostgreSQL**: v16 with `pgvector` extension enabled (e.g. Neon PostgreSQL)
- **ImageKit**: Free account for direct-upload CDN image storage

### 3.2 Backend Setup (Node.js Orchestrator)
1. Navigate to the backend directory:
   ```bash
   cd backend
   npm install
   ```
2. Create `backend/.env` with the following variables:
   ```env
   PORT=3000
   DATABASE_URL="postgresql://<user>:<password>@<host>/<dbname>?sslmode=require"
   JWT_SECRET="your-super-secret-jwt-key"
   JWT_EXPIRES_IN="7d"

   AI_SERVICE_URL="http://localhost:8000"

   IMAGEKIT_PUBLIC_KEY="your_imagekit_public_key"
   IMAGEKIT_PRIVATE_KEY="your_imagekit_private_key"
   IMAGEKIT_URL_ENDPOINT="https://ik.imagekit.io/your_id"
   ```
3. Push Prisma schema to the database:
   ```bash
   npx prisma db push
   ```
4. Start the Node.js backend server:
   ```bash
   npm run dev
   # Server runs on http://localhost:3000
   ```

### 3.3 AI Microservice Setup (FastAPI)
1. Navigate to the AI directory:
   ```bash
   cd ai
   python -m venv venv
   # On Windows:
   .\venv\Scripts\activate
   # On macOS/Linux:
   source venv/bin/activate
   pip install -r requirements.txt
   ```
2. Create `ai/.env` with the identical JWT secret:
   ```env
   PORT=8000
   DATABASE_URL="postgresql://<user>:<password>@<host>/<dbname>?sslmode=require"
   JWT_SECRET="your-super-secret-jwt-key"
   JWT_ALGORITHM="HS256"
   ```
3. Run the AI service:
   ```bash
   # On Windows (set UTF-8 to prevent console emoji errors):
   $env:PYTHONUTF8=1; uvicorn app.main:app --port 8000 --reload
   # On macOS/Linux:
   uvicorn app.main:app --port 8000 --reload
   ```

## 4. Unified Database Schema Architecture

PostgreSQL acts as the single source of truth, combining relational tables (managed by Prisma ORM) with vector columns (managed by FastAPI via SQLAlchemy and `pgvector`).

```
  ┌────────────────────────────────────────────────────────────┐
  │                 users                                      │
  │  - id: UUID (PK)                                           │
  │  - email: VARCHAR(255) (Unique)                            │
  │  - password_hash: VARCHAR(255)                             │
  │  - full_name: VARCHAR(100)                                 │
  │  - username: VARCHAR(50) (Unique)                          │
  │  - is_premium: BOOLEAN                                     │
  └─────────────┬──────────────────────────────────────────────┘
                │
                ├──────────────────────────────────────┐
                │ 1:1                                  │ 1:N
                ▼                                      ▼
  ┌─────────────────────────────┐        ┌─────────────────────────────┐
  │ user_profiles               │        │ group_members               │
  │  - user_id: UUID (PK, FK)   │        │  - group_id: UUID (FK)      │
  │  - dietary_preference       │        │  - user_id: UUID (FK)       │
  │  - travel_style             │        │  - role: 'creator' |        │
  │  - budget, budget_tier      │        │          'admin' | 'member' │
  │  - pace_preference          │        └─────────────┬───────────────┘
  │  - health_constraints       │                      │
  │  - preference_vector: VECTOR│                      │ N:1
  └─────────────────────────────┘                      ▼
                                         ┌─────────────────────────────┐
  ┌─────────────────────────────┐  1:1   │ trip_groups                 │
  │ group_consensus_profiles    │<───────┤  - id: UUID (PK)            │
  │  - group_id: UUID (FK, Uni) │        │  - name: VARCHAR(150)       │
  │  - computed_budget_range    │        │  - status: 'planning' |     │
  │  - hard_constraints         │        │    'ongoing' | 'completed'  │
  │  - consensus_vector: VECTOR │        │  - chat_retention_deadline  │
  │  - is_locked_by_admin       │        │  - preserve_chat: BOOLEAN   │
  └─────────────────────────────┘        └─────────────┬───────────────┘
                                                       │
                      ┌───────────────────┬────────────┴───────┬───────────────────┐
                      │ 1:N               │ 1:N                │ 1:N               │ 1:N
                      ▼                   ▼                    ▼                   ▼
       ┌────────────────────────┐ ┌───────────────┐ ┌────────────────────┐ ┌──────────────┐
       │ messages               │ │ polls         │ │ expenses           │ │ itineraries  │
       │  - content             │ │  - question   │ │  - amount          │ │  - version   │
       │  - created_at          │ │  - poll_vector│ │  - status: approved│ │  - is_active │
       │  (Purged on retention) │ └───────────────┘ └──────────┬─────────┘ └──────┬───────┘
       └────────────────────────┘                              │                  │
                                                               │ 1:N              │ 1:N
                                                               ▼                  ▼
                                                    ┌────────────────────┐ ┌──────────────┐
                                                    │ expense_splits     │ │itinerary_item│
                                                    │  - user_id (FK)    │ │ - day_number │
                                                    │  - amount_owed     │ │ - activity   │
                                                    └────────────────────┘ └──────────────┘
```

### 4.1 Data Retention & Privacy Engine
* **Ephemeral Data:** Raw rows in `messages` and local receipt buffers are automatically deleted by the daily retention cron job (`02:00 AM`) 5 days after `trip_end_date`, unless `preserve_chat = true`.
* **Permanent Data:** `trip_memories` (the photo vault), `expenses`, `expense_splits`, `settlements`, `itineraries`, and `interaction_embeddings` (vector context) are **permanently retained**.

* **Access:** Trip Member

* **Access:** Trip Admin Only

  ```json
  {
    "amount": 1200.00,
    "description": "Seafood Dinner (Excluding Charlie)",
    "splitMemberIds": ["alice_id", "bob_id"]
  ```

#### `DELETE /api/trips/:tripId/expenses/:expenseId`
**Admin Override:** Deletes an expense from the ledger. Splits cascade-delete.
* **Access:** Trip Admin Only

#### `POST /api/trips/:tripId/expenses/:expenseId/discuss`
Shares a questioned expense directly into the trip chat with **automatic tagging of the payer (`@payer`)**.
* **Access:** Trip Member
* **Body:**
  ```json
  {
    "message": "Hey Alice, was I charged for drinks here? I didn't drink alcohol."

  ```

  1. Formats message: `@alice 🧾 Objection/Query regarding "Seafood Dinner" (Total: ₹1,500.00, My share: ₹500.00): "Hey Alice, was I charged for drinks here?"`
  2. Saves record to `messages` table.
  3. Broadcasts WebSocket event `message` (chat feed) and `EXPENSE_DISPUTED` (flags expense card).

#### `GET /api/trips/:tripId/expenses/settlements`
Fetches the current debt settlement plan (who pays whom).
* **Access:** Trip Member
* **Response (200 OK):**
  ```json

    "status": "success",
    "data": {

        {
          "id": "set_1",
          "payer": { "id": "bob_id", "fullName": "Bob" },

      ]

  }
  ```

#### `POST /api/trips/:tripId/expenses/settlements/calculate`
Runs the **Greedy Min-Cash-Flow Algorithm** to calculate and store the optimal debt settlement plan.
* **Access:** Trip Admin Only

#### `PATCH /api/trips/:tripId/expenses/settlements/:settlementId/complete`
Marks an individual debt transaction as settled.
* **Access:** Payer or Trip Admin

### 5.7 Structured Itinerary Engine API (`/api/trips`)

Mounted at `/api/trips`.

## 7. Core Algorithmic Engines

### 7.1 Group Consensus Modeling (Centroid Math)
Individual preference vectors $\vec{v}_i \in \mathbb{R}^{384}$ are generated by local sentence-transformers. The group consensus vector $\vec{C}$ is calculated as the normalized centroid:

$$\vec{C} = \frac{\sum_{i=1}^{N} \vec{v}_i}{\left\| \sum_{i=1}^{N} \vec{v}_i \right\|}$$

This centroid maximizes the average cosine similarity across all group members:

$$\arg\max_{\vec{C}} \frac{1}{N} \sum_{i=1}^{N} \cos(\vec{C}, \vec{v}_i)$$

FastAPI searches destination catalogs using cosine distance operator `<=>`:
```sql
SELECT id, name, avg_daily_cost, (destination_vector <=> :consensus_vector) AS distance
FROM destinations_catalog
ORDER BY distance ASC
LIMIT 10;
```

---

### 7.2 Greedy Min-Cash-Flow Settlement Algorithm
At the end of a trip, pairwise transaction reconciliation can result in circular debt (e.g., A owes B, B owes C, C owes A).

1. For every member $i$, compute net balance:
   $$\text{netBalance}_i = \text{totalPaid}_i - \text{totalOwed}_i$$
   * $\sum_{i=1}^{N} \text{netBalance}_i = 0$ *(Zero-sum invariant guaranteed)*
2. Separate members into two priority heaps:
   - **Creditors:** Members with $\text{netBalance} > 0$, sorted descending by credit.
   - **Debtors:** Members with $\text{netBalance} < 0$, sorted descending by absolute debt.
3. Greedily match the largest debtor with the largest creditor:
   $$\text{settledAmount} = \min(\text{credit}_{\max}, \text{debt}_{\max})$$
4. Record transaction: `Debtor pays Creditor settledAmount`.
5. Deduct from balances and repeat until all debts reach $0.00$.

> **Result:** Resolves an $N$-person debt graph in at most $N-1$ transactions.

### 7.3 Multimodal Receipt OCR Pipeline
1. Client uploads receipt screenshot to ImageKit CDN.
2. Node.js sends fire-and-forget POST to FastAPI `/api/ai/ocr/receipt`.
3. Image buffer is decoded into grayscale.
4. Line detection isolates numerical totals using regex patterns accommodating Indian and international markers:
   ```python
   _AMOUNT_RE = re.compile(
       r'(?:[₹]|Rs\.?|INR|Total|Grand\s*Total|Amount\s*Paid|Net\s*Amount|Paid)'
       r'\s*:?\s*([0-9]{1,6}(?:,[0-9]{2,3})*(?:\.[0-9]{1,2})?)',
       re.IGNORECASE,
   )
   ```
5. Returns extracted numerical value. Node.js updates expense record to `approved`, creates equal splits, and emits `EXPENSE_OCR_COMPLETED` over WebSockets.

### 7.4 Algorithmic Memory Highlight Scoring
100% internal logic running on local server CPU:
* **EXIF Metadata Parsing:** Extracts binary camera headers (`DateTimeOriginal`, GPS coordinates) in ~2ms using `exifr`.
* **Heuristic Scoring Function ($0.0 \to 1.0$):**
  - Base score: `0.50`
  - Descriptive user caption: `+0.15`
  - Location or GPS tag: `+0.10`
  - Matches scheduled itinerary activity: `+0.15`
* Photos with `highlightScore >= 0.70` automatically become `aiHighlight = true` and populate the top story reel.
